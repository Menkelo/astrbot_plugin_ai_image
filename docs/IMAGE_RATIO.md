# 图片比例：1.7.6–1.7.9 复盘与新方案

## 结论

这些版本反复修补的是同一个问题：模型或中转站没有严格按参考图画幅返回图片，而插件试图通过生成后的裁剪恢复比例。生成模型可能改动整体构图，因此“那一片颜色很均匀”不能证明它属于可以删除的补边。

1.8.1 采用已选定的策略：**保留模型返回的完整内容，必要时补边**。不再通过颜色或近白像素比例判断裁剪范围。

## 历史行为

| 版本 / 提交 | 实际做法 | 留下的问题 |
| --- | --- | --- |
| 1.7.6 / `9750bf5` | 参考图先匹配最接近的固定比例，再按该比例裁剪输出 | 任意比例可能被映射成 9:21 等其他画幅；比例推断与用户明确要求被混在一起 |
| 1.7.7 / `f6a2769` | 读取参考图实际尺寸并对齐后请求；取消自动套最近比例 | 原始像素不一定满足接口的最小面积等约束，中转站也可能忽略尺寸 |
| 1.7.7 / `8e14b62` | 增加生成后裁回参考图比例，再缩放到参考图像素 | 如果模型已经重新构图，直接裁剪会截掉内容 |
| 1.7.7 / `6a4198f` | 改用 `size=auto`，去掉强制回裁 | 画幅完全依赖接口选择，不能保证与参考图一致 |
| 1.7.7 / `ac1fe88` | 输入先补成白底正方形，要求模型保持补边，再裁回原比例 | 模型并不一定保留补边、主体位置和缩放关系；所有图片还被描述成 screenshot |
| 1.7.8 / `7cd4a77` | 两侧均达到 90% 近白像素才回裁，否则跳过 | 少量但重要的边缘内容仍可能被裁；跳过后又不能保证目标比例 |
| 1.7.9 / `a9aec3e` | 允许近白边缘或 RGB 各通道标准差小于 15 的均匀颜色区域参与回裁 | 天空、墙面、背景及细小主体部分也可能满足这些条件，仍无法可靠区分“补边”和“内容” |

1.7.7 包含数次没有再次变更版本号的算法调整，因此不能仅凭“1.7.7”确定当时使用了哪一种策略。[CHANGELOG](../CHANGELOG.md) 使用具体 Git 提交划分历史。

## 本地复现

使用 512×512 的程序绘制图片，目标设为 1:2，直接运行原 1.7.9 方法：

- 白底人物的双臂伸向两侧。旧算法将两侧判为空白，输出 256×512；红色手臂标记从 3628 个像素减少到 2271 个。新算法输出 512×1024，原始 512×512 内容逐像素完整保留。
- 边缘带明显纹理时，旧算法跳过回裁，输出仍为 512×512。新算法同样补成 512×1024，结果不依赖图像颜色。

这是对本地后处理的确定性复现，不是线上模型质量评测。

## 新的处理流程

1. **确定目标**：优先使用指令/预设指定的比例，否则使用第一张参考图实际宽高；先处理 EXIF 方向。没有比例也没有参考图时，不额外限制本地画幅。
2. **保留参考图**：多张参考图保留各自原有画幅。第一张决定默认目标，后续图片作为辅助，不先补白边或改成正方形。
3. **选择接口参数**：只有参考比例与已支持枚举完全相等时才传该枚举，任意特殊比例不就近吸附。GPT Image 2 / 2.5 可以选择合法的自定义尺寸；接口请求画幅和本地最终目标分别保存。
4. **引导构图**：提示模型保留完整主体，必要时向外扩展背景；不再把所有参考图称为“白底正方形截图”。
5. **统一处理结果**：所有提供商和备用接口都先应用输出 EXIF 方向，再以等比适配和补边满足同一个本地目标，不做裁剪或非等比拉伸。
6. **约束资源**：正常尺寸保留原始像素。补边画布超过 4000 万像素或单边 16384 像素时，等比缩小完整结果后放入画布。整数像素存在少量舍入误差；无法在限制内表示的极端比例会记录日志并保留完整返回图。
7. **独立定义分辨率，统一计算画布**：分辨率档位不会反过来修改目标比例。Gemini/Vertex 使用其分辨率长边规则；GPT Image 2 / 2.5 使用本插件的合法尺寸预设及该模型的限制。需要放大时直接按真实比例计算最终画布，并只对内容等比缩放一次，避免放大小画布的舍入误差。

有实际透明像素的图片补透明边，其他图片补白边。补边可能增大最终画布，因此“参考图比例”“请求尺寸”“最后输出像素”是三个不同概念；本地等比放大不会凭空增加模型生成的细节。

这套流程保证插件不主动裁掉模型已经返回的画面。模型生成时若已遗漏参考图中的元素，客户端后处理无法将它们还原。也不增加“比例不符就重新生成”的自动重试，避免仅为调整画幅反复调用收费模型。

## 接口规则核对

依据 [官方 OpenAI 图像生成文档中的 GPT Image 2 章节](https://developers.openai.com/api/docs/guides/image-generation#earlier-gpt-image-models)：

- `size` 的两条边必须是 16 的倍数，单边不超过 3840，长短边比不超过 3:1，总像素在 655,360–8,294,400 之间。
- `auto` 是支持的选项，但不等于“保证与参考图尺寸相同”。
- GPT Image 2 自动采用高保真图像输入，官方明确要求省略 `input_fidelity`。

本插件的尺寸表是满足上述约束的预设，不是适用于所有 GPT Image 模型的官方固定枚举。GPT Image 1 系列使用其固定尺寸集合。未知模型别名使用 `auto`，最终仍按独立保存的目标补边。

GPT Image 2.5 Sunburst / Flare 也支持上述自定义尺寸约束，插件会识别 2.5 家族并直接发送合法尺寸。质量档位与背景参数的差异见 [GPT Image 2.5 适配](GPT_IMAGE_25.md)。

OpenAI 图像接口只在结构化错误明确给出被拒绝的尺寸/保真参数时降级一次。比如仅 `input_fidelity` 不兼容时，只移除该字段，不连带丢掉合法的 `size`；其他 400 不盲目重试。
